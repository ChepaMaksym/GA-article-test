# Перенесення самоналаштовуваного (1+(λ,λ)) GA до гармонізованого пошуку ознак CHC: модель, верифікація та межі застосовності

Науковий звіт до магістерської роботи. Дата: 9 вересня 2026 року.
Дослідження `EU26-21-CWB-01`, протокол `EU26-21-COMMON-WBA-BSF-AUC-400-V1`.
Це завершений звіт про підтверджувальний експеримент, а не оформлений за
невідомим шаблоном університету повний рукопис із титульною сторінкою.

## Анотація

Реалізовано й перевірено перенесення відомого самоналаштовуваного пошуку
`(1+(λ,λ))` до задачі вибору бінарної маски ознак. Порівняння з гармонізованим
CHC використовує спільні дані, objective, початкові маски та бюджет. Повна
кампанія GitHub Actions отримала 30 пар; незалежний від запуску пошуку етап
повторно перевірив усі artifacts і переагрегував результати.

Гіпотезу збереження якості в межах −0,10 відсоткового пункту **не підтверджено**.
Медіана парної різниці official-test weighted balanced accuracy становить
−0,013734 в.п.; 95% BCa-інтервал — [−0,208726; +0,151807] в.п. Нижня межа
не проходить зафіксований поріг. Позитивну різницю validation best-so-far AUC
та медіану парної різниці кількості ознак −1 збережено як описові спостереження; вони
не є успішною спільною заявою про якість та ефективність. Результат обмежує
підтримувані твердження про застосовність методу, але не доводить його
однозначної гіршості: інтервал якості також містить нуль.

## 1. Проблема та внесок

Об'єкт — стохастичний wrapper-пошук підмножини ознак для класифікації Census.
Предмет — перенесення feedback-керування λ за однакової одиниці витрат
пошуку. Мета — перевірити, чи спостережувана пошукова перевага зберігається
разом із допустимою якістю на corrected official-UCI протоколі.

Hevia Fajardo–Sudholt досліджують параметричне керування `(1+(λ,λ))` GA.
Ця робота дає механізм і теоретичну мотивацію, але не гарантію його
ефективності для WBA дерева рішень на масках ознак. Altarabichi et al.
розглядають CHC-QX із qualitative approximation. Новий експеримент бере
з цієї прикладної лінії задачу і пошукові оператори CHC, проте гармонізує
evaluator, вилучаючи learned instance selection та зовнішній evolution
control. Тому це не буквальне відтворення повного CHC-QX.

Інкрементальний внесок — відтворювана специфікація перенесення, чесне
парне порівняння пошукових компонентів, формальна модель обліку витрат,
перевірювані фінальні класифікатори та емпірична межа підтримки спільної
гіпотези. Формула GA, правило 1/5, CHC, Decision Tree, WBA і bootstrap
не оголошуються новими. Відмінності від PR8 та лінії PR23/26/27 наведено
в [огляді пов'язаних робіт](RELATED_WORK_UK.md). Світовий пріоритет не доведено.

## 2. Формальна модель

Маска `z ∈ {0,1}^40` визначає ознаки класифікатора `h_z`. Для непорожньої
маски максимізується лексикографічна пара

```text
f(z) = (WBA_validation(h_z), −sum(z)/40).
```

Для порожньої маски наперед зафіксовано `f(0)=(0,−1)`. Якість має абсолютний
пріоритет над компактністю. Weighted balanced accuracy — середнє зважених
recall двох класів; ваги спостережень використовуються також під час fitting.
Після 400 викликів обирається найкраща запитана маска; точна рівність обох
компонентів розв'язується на користь ранішого objective call.

Стан lambda-пошуку містить parent, його fitness, λ, лічильник і власний RNG.
Для `n=40`, `F=1.5`:

```text
m = floor(λ + 0.5),  p = λ/40,  c = 1/λ;
строге покращення: λ' = max(1, λ/F);
інакше:            λ' = min(40, λ·F^(1/4)).
```

Одна mutation-фаза та одна crossover-фаза утворюють пару. Mutation міняє
різні позиції маски; crossover бере алелі parent і найкращого mutant.
Reset lambda вимкнений. Cataclysmic restart CHC — інша операція, не lambda-reset.

Індукцією з `λ=1` отримуємо `1≤λ≤40`; отже `p,c∈[0,1]`. Оператори
зберігають бінарність. Оновлення terminal best тільки за строгого
лексикографічного покращення гарантує неспадання його WBA. Ledger фіксує
кожен objective call, включно з повторними й порожніми масками; caching
вимкнено. Спільні 50 початкових викликів залишають парний бюджет 350 для
lambda-фаз. Часткове останнє покоління обох методів обробляється за
наперед визначеними правилами, а не за отриманою якістю.

Власне алгебраїчне пояснення feedback: якщо обидва можливі оновлення не
обрізаються межами й умовна ймовірність строгого успіху дорівнює `s`, то

```text
E[Δlog λ | state] = −s·log F + (1−s)·log F/4
                 = (1−5s)·log F/4.
```

Нульовий дрейф при `s=1/5` пояснює зворотний зв'язок, але не є новою
теоремою збіжності чи доведенням прискорення на цій задачі.

Bridge починається з 50 спільних source-density масок: lambda-parent
обирається серед їхніх найкращих, а не з одного рівномірного випадкового
бітового вектора канонічного алгоритму. Це, зміна objective, обмеження
бюджету й terminal rule є явними адаптаціями. Деталі та уточнення номера
алгоритму у прикладному першоджерелі наведено в
[моделі й верифікації](MODEL_AND_VERIFICATION.md); frozen-протокол не переписано.

## 3. Зафіксований експериментальний метод

| Компонент | Зафіксоване значення |
| --- | --- |
| Групи | `chc_harmonized`, `lambda_no_reset` |
| Дані | Official UCI Census-Income KDD: 199 523 training, 99 762 test рядків |
| Маска | 40 предикторів; raw instance-weight index 24 виключено |
| Ваги | Використовуються у fitting та weighted metrics, не є предиктором |
| Підготовка | Train-only preprocessing; numeric scaling та categorical ordinal encoding |
| Модель | `DecisionTreeClassifier(random_state=0)` |
| Validation | 20% official-training файлу; paired stratified split |
| Активна вибірка | 14 964 спільні training-рядки в парі |
| Ініціалізація | Однакові впорядковані 50 масок у парі |
| RNG | Ізольовані потоки split, active sample, initial masks та кожного пошуку |
| Бюджет | Рівно 400 logical objective calls на групу і seed |
| Нові seeds | 41001–41030; жодного відбору за результатом |
| Test | Одне фінальне metric-evaluation на групу після фіксації обох traces |
| Bootstrap | Парна медіана; 50 000 BCa-реплік; seed 41031; двосторонній 95% CI |
| Lambda-reset | Вимкнений; reset count = 0 |

Terminal classifier fitted на внутрішній 80% training-частині, не на test.
Зберігаються fitted preprocessing, модель, маска, назви ознак та provenance.
Точний reload перевіряється на перших восьми training-рядках; цей probe не
оцінює test і не бере участі у виборі маски. Сторонні downloaded joblib
пакети агрегатор не десеріалізує: перевіряє байтові хеші й записи верифікації.

Ефективність визначена як `AUC_a = sum(best_so_far_WBA_a[k], k=1..400)/400`.
Це площа траєкторії якості за logical calls, не ROC-AUC, PR-AUC або час.
Оскільки початкові 50 оцінок спільні, для парної різниці
`ΔAUC_1:400 = 0.875·ΔAUC_51:400`. Tail-AUC лише масштабує контраст і
не створює другого незалежного підтвердження.

Спочатку потрібне `lower95BCa(Δtest-WBA)>−0.001`. Тільки після цього
`lower95BCa(ΔAUC)>0` підтримує спільну заяву про пошукову ефективність.
Розмір маски є вторинним. Ці умови та порядок не змінювалися після outcomes.

## 4. Верифікація та виконання

Усі виконувані перевірки, fitting, пошук, статистика та агрегація відбулися
в GitHub Actions. Локально виконувалися читання/редагування і git-операції,
не pytest, статистичні скрипти, MATLAB/Octave, lint чи експерименти.

На дослідницькому SHA `79c9b154206cdc3d318b90b598c7f0f48ca02b53` quality CI
завершив 112 тестів успішно. Перевірено λ, оператори, типи масок, облік
викликів, детермінізм, спільну ініціалізацію, test-access barrier, модельний
reload, повний синтетичний runner→30 пар→aggregate, негативні evidence-кейси,
змішані infrastructure attempts та незалежний BCa-еталон. HUX порівняно
з pinned-кодом авторів і наступним станом RNG. Окремий CI виконав реальний
upload/download probe. Загальне coverage в quality-звіті — 61%; тести й
огляд не оголошуються формальним доведенням відсутності всіх програмних помилок.
Сім некритичних lint-зауважень у попередньому коді залишаються видимими;
critical lint, high-severity security та modern corrected dependency gates пройдено.
Окремий неблокувальний аудит історичного середовища зберігає повідомлення
`PYSEC-2024-110` для `scikit-learn==1.2.2`; зелений CI не означає, що це
архівне середовище не має відомих вразливостей. Воно не підміняє modern
corrected середовище нового bridge; історичні залежності не переписувалися.

На reporting SHA `4a4bf9ebe5d1385689172fa5fc7a92ced2a5b91b` повний quality CI
виконав 117 тестів, зокрема п'ять нових перевірок описового звіту; coverage —
62%. Усі три blocking CI workflows зелені. Додаткові reporting-тести
перевіряють цілісність входів і незмінність рішень, не додають нових
експериментальних спостережень.

Перший manual run `34192825801` мав дефект каталогу розпакування fixture.
Усі 30 optimizer steps були skipped; жодного scientific row він не створив.
Тег v1 збережено. Після виправлення лише orchestration і нового зеленого CI
створено v2 на зазначеному SHA. [Журнал відновлення](INFRASTRUCTURE_RECOVERY.md)
відділяє цей infrastructure failure від наукового рішення.

Другий run завершив усі 30 paired jobs і агрегацію без помилок. Кожен seed
має сім файлів: row, два traces, status, manifest і дві fitted models —
разом 210 файлів та 60 модельних пакетів. Повторна агрегація отримала лише
зафіксовані 30 IDs, перевірила ZIP SHA-256, per-file hashes, схеми, повноту,
унікальність, provenance, transitions і terminal state без повторного пошуку.

## 5. Підтверджувальні результати

Усі контрасти нижче — `lambda_no_reset − chc_harmonized`. Статистика —
медіана **парних** різниць, не різниця двох окремих медіан.

| Показник | Парна медіана | 95% BCa | Рішення |
| --- | ---: | --- | --- |
| Official-test WBA, в.п. | −0,013734 | [−0,208726; +0,151807] | NI не підтверджено; межа −0,10 в.п. |
| Best-so-far AUC, calls 1–400 | +0,001935522 | [+0,001234791; +0,003150039] | Підтверджувальна заява заблокована quality gate |
| Tail-AUC, calls 51–400 | +0,002212025 | [+0,001411190; +0,003600044] | Лише описово; не незалежний ефект |
| Кількість ознак | −1 | Не був заданий окремий CI-критерій | Вторинний описовий показник; перевага не заявляється |

Lambda вибрав менше / стільки ж / більше ознак у 16 / 4 / 10 парах.
Усі 30 пар збережено. Немає вибору favorable seeds, повторної оптимізації
для зміни рішення чи підлаштування margin.

Межі quality CI охоплюють нуль та значення нижче −0,001. Отже дані сумісні
як із невеликою перевагою, так і з неприйнятною за протоколом втратою;
еквівалентність або non-inferiority не встановлено. Позитивна validation
траєкторія не гарантує достатньої official-test якості. Цей дизайн не
ідентифікує причину розбіжності як «overfitting», reset чи адаптацію λ.

Машинні значення без округлення містяться в
[перевіреному повторному звіті](evidence/reaggregated-report.json).

нового 400-call AUC-дослідження. Reset не оголошується причиною ефекту.

## 7. Обмеження та висновок для магістерської

Тридцять seeds дають умовну seed/split-реплікацію на одному dataset і
спільному official test, не 30 незалежних прикладних задач. Цей test уже
використовувався в історичній дослідницькій лінії: нові seeds не роблять його
глобально новим зовнішнім holdout. Prospective протокол був зафіксований до
нових outcomes, але інформований попередніми результатами. 50 000 bootstrap
реплік не збільшують фактичний обсяг вибірки.

Порівнюються повні гармонізовані пошукові компоненти. Без fixed-λ абляції
не відокремлено причинний внесок саме adaptation; без повного QX pipeline
не оцінено його learned qualitative model. Один classifier, бюджет і dataset
не дозволяють переносити висновок на інші задачі або витрати в секундах.

Підсумкове твердження: запропоновано й відтворювано перевірено інтеграцію
відомого параметричного керування в гармонізований бінарний пошук ознак.
За однакового бюджету спостерігається краща validation BSF-траєкторія,
але на заданій точності та обсязі підтверджувального досліду не встановлено
official-test non-inferiority. Тому заяву про збереження якості разом із
пошуковою перевагою відхилено за наперед визначеним правилом.
Це валідний негативний результат перевірки гіпотези, не провал виконання CI.

Окреме майбутнє дослідження може перевірити зовнішні datasets або розділити
внесок контролера та інших операторів. Такі запуски не виконувалися і не
використовуються для «порятунку» поточного рішення. Для повного оформлення
магістерської потрібні вимоги кафедри, титульні реквізити й бібліографічний
стиль; їх неможливо достовірно вигадати з коду.
