# Перевірюване покоління для дослідження локальних оптимумів

Дата специфікації: 23 вересня 2026 року.
Статус: окремий програмний компонент нового етапу; не наукова кампанія
та не результат відтворення опублікованих чисел.

## Обґрунтування й межі допуску

Компонент продовжує вже наявний EU26-21 та усуває розбіжність,
знайдену в [аудиті реалізації](../IMPLEMENTATION_AUDIT_2026-09-10_UK.md).
Нову статтю або зовнішню реалізацію цим кроком не вводять. Використовуються
власні наявні оператори `hybrid_1/core.py`; історичний runner і його
результати залишаються незмінними. Підстава одноразового вибору мутанта —
Algorithm 3 у [статті Hevia Fajardo–Sudholt](https://mhevia.com/assets/pdf/journal_oplclga.pdf).
Цей крок не надає новим літературним кандидатам статусу `hard_pass`.

Переглянута вихідна версія локального коду:
`baa8b4c49f99ede8d1eb932a6ab3aac6c85c0763`.
Код не копіюється з нового зовнішнього пакета. Нова специфікація
стосується лише переходу одного покоління й журналу викликів;
вона не встановлює бюджет, seed або поріг наукового ефекту.

## Контракт одного покоління

`generation.py` надає `run_generation` з явними входами: цільова функція,
батьківська маска та її вже відома оцінка, λ, коефіцієнт F,
прапорець скидання, власний RNG і початковий номер викликів.

1. Для `n` бітів використовується `m=floor(λ+0.5)`, `p=λ/n`, `c=1/λ`.
2. Спільне `L~Bin(n,p)` визначає число різних змінених бітів кожного мутанта.
3. Кращого мутанта вибирають один раз. Його індекс визначає як батька
   схрещування, так і мутанта у фінальному пулі.
4. Копії поточної батьківської маски виключають із фінального відбору;
   інші дублікати зберігаються як окремі елементи вибірки.
5. Нестроге покращення допускає заміну батька, але лише строге
   лексикографічне покращення є успіхом для оновлення λ.
6. Скидання λ після невдачі на межі `n` не створює нової маски.
7. Виконуються рівно `2m` викликів: спочатку мутанти, потім нащадки
   схрещування. Батьківську оцінку не переобчислюють. Її відповідність
   тій самій детермінованій цільовій функції є передумовою виклику.

Журнал зберігає маску, повну оцінку, номер виклику, фазу й індекс
нащадка. Перший запит зі строгим покращенням відокремлено від
прийняття кандидата наприкінці покоління. Саме по собі покращення
ще не називається виходом із локального оптимуму: для цього потрібні
означення події та підтверджений початковий стан у майбутньому протоколі.

`select_from_chosen_mutant` приймає вже вибраний індекс. Він перевіряє
належність цього індексу до найкращих мутантів і не повторює вибору
серед них. Випадковий вибір фінального кандидата за нічиєї — інша,
окрема операція, передбачена алгоритмом.

## Перевірки

Нові модульні тести виконуються лише в GitHub Actions разом з
існуючим набором EU26-21. Вони охоплюють контрольовану нічию між
двома різними мутантами, ідентичність батька схрещування, облік
повторних оцінювань, нейтральне прийняття, оновлення λ, детермінізм
і відхилення некоректних входів до початку випадкових операцій.

Ці перевірки не запускають нової підтверджувальної серії і не
збільшують кількості наукових спостережень. Зелений CI засвідчує
виконання програмного контракту, а не наявність переваги методу.

## Наступні залежності

Ще потрібні окремий протокол повного пошуку, політика останнього
покоління, облік цензурування, перевірка околу `N₁`, допустимість
додаткових методів, фіксований λ як контроль і реєстр нових seed.
До їх фіксації тут немає runner-а наукової матриці, агрегації чи
висновку про ефективність. Загальна постановка:
[RESEARCH_OBJECTIVE_UK.md](../RESEARCH_OBJECTIVE_UK.md).
