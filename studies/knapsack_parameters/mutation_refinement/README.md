# Уточнення сталої та адаптивної мутації

Стан: підготовлено prospective реалізацію; нові перевірки, підготовку входів і технічний пілот ще не виконано. [Ресурсний дозвіл](resource_authorization.json) має `explicit_user_approval=false`. Сам факт наявності workflow або програмного коду не є дозволом обчислень.

[Протокол](PROTOCOL_UK.md) зареєстровано до нового правила в `ef211e41bc0803d29369ec44412aa099cf0e2e71`, SHA-256 `032576358a6adc27e2a45b57151d2d6ea69c78859e0295a70416656632370dc6`. [Допуск](ADMISSION_UK.md) і [джерела](SOURCES_UK.md) відрізняють власну евристику від числової реплікації статей. Новизна й емпірична перевага не встановлені. Історичні ядра, результати, невдалі спроби та незавершений λ-напрям не змінюються.

## Технічний контракт

Після окремого явного погодження можливий сумарний ліміт **60 runner-хвилин** на три послідовні фази одного [workflow](../../../..//.github/workflows/knapsack-mutation-refinement.yml). Це окремий бюджет; старі залишки не використовуються. Усі попередні спроби цього workflow, включно з невдалими й скасованими, враховуються з округленням тривалості кожного виділеного job угору до хвилини. Невідомий час, недоступний API, неповний ресурсний стан або відсутній дозвіл блокують роботу.

| Фаза в єдиному маркері commit message | Резерв, хв | Призначення |
| --- | ---: | --- |
| `[mutation-refinement:tests]` | 9 | Програмні приклади, без наукової серії |
| `[mutation-refinement:prepare-pilot]` | 7 | Вісім спільних початкових банків після замороженого успішного звіту тестів |
| `[mutation-refinement:pilot]` | 34 | 40 технічних проб після окремого заморожування входів |

Сума початкових резервів — 50 хвилин, залишок 10 хвилин враховує можливі повторення; кожна нова спроба знову проходить перевірку доступного залишку. Timeouts: gate 1, tests 6, prepare 4, кожний worker 6, aggregate 4 хвилини. Максимум чотири workers, `fail-fast=false`; workflow виконується послідовно, `cancel-in-progress=false`. На scientific калібрування, основну серію або нові точні еталони фаз немає.

Виконання прив'язано до точного `github.sha`, потрібної гілки й репозиторію, чистих tracked-файлів та незміненого протоколу. Runtime: Python **3.12.14**, Ubuntu 24.04 і наявні залежності `ga_study/dependencies/requirements.lock`, установлені через `--require-hashes --only-binary=:all:`. Їхні файли й версії перевіряються. Відбиток походження містить локальні код, тести, Markdown, workflow, залежності й використані історичні джерела. Зміна будь-якого з них робить попередній успішний звіт непридатним; потрібні нові перевірки в межах залишку бюджету.

## Послідовність заморожування

Pipeline не пушить і не комітить артефакти. Після дозволеної успішної фази `tests` зберегти **весь** артефакт `mutation-refinement-tests-RUN-ATTEMPT` до окремого каталогу `evidence/tests-RUN-ATTEMPT/` із його `file_manifest.json`. Поза pipeline підготувати `frozen_tests.json`:

```json
{
  "frozen": true,
  "receipt_path": "evidence/tests-RUN-ATTEMPT/tests_receipt.json",
  "receipt_identity": {"bytes": 0, "sha256": "ACTUAL_RECEIPT_SHA256"},
  "artifact_id": 0,
  "zip_sha256": "ACTUAL_GITHUB_ARTIFACT_DIGEST"
}
```

Нулі та назви-заповнювачі замінюються фактичними значеннями; це приклад схеми, не чинний дозвіл або доказ. Зробити окремий data-only commit лише цього descriptor і відповідного каталогу evidence. Код перевіряє успіх точної CI-спроби, початковий source fingerprint, Git-байти окремого freeze-коміту та незмінений доступний artifact за ID і digest. Простого `tests_passed=true` без цих доказів недостатньо.

Після дозволеної успішної `prepare-pilot` зберегти **весь** артефакт `mutation-refinement-inputs-RUN-ATTEMPT` до `inputs/pilot/` і створити `frozen_pilot_banks.json`:

```json
{
  "frozen": true,
  "stage": "pilot",
  "registry_identity": {"bytes": 0, "sha256": "ACTUAL_BANK_REGISTRY_SHA256"},
  "artifact_id": 0,
  "zip_sha256": "ACTUAL_GITHUB_ARTIFACT_DIGEST"
}
```

Окремий наступний data-only commit має містити лише цей descriptor і `inputs/pilot/`. Пілот не стартує в тому самому pipeline, де готували банки. Артефакти мають зберігання 90 днів; їхню доступність не видають за безстрокове збереження. До спливу строку потрібне окреме збереження повних доказів і перевірка hashes.

## Входи, запуски та облік

Чотири старі задачі: `UC-s000`, `WC-s001`, `SC-s005`, `SC-s000`. Вісім банків — ці чотири задачі з початками `cloned` і `bank`, у цьому порядку індексів 0 і 1. `cloned` містить 30 копій історичного центру; `bank` — порожню маску й 29 незалежних бінарних масок з імовірністю біта 0.5. Окремий підготовчий PCG64 використовує `SeedSequence([97998, task_index, start_index, 97999])`. Кожна унікальна маска оцінюється один раз на банк; 30 логічних позицій та незалежні перевірки оцінок рахуються окремо.

Незмінений `two_signal_mutation.banks.source_case(task, 'pilot')` лише читає й перевіряє старі байти, центр та вже наявні точні еталони. Історичний ресурсний grant не викликається. Зовнішній оптимум зберігається поза входом пошуку. Кожен із чотирьох workers виконує 10 проб: два спільних банки × `fixed_0.005`, `fixed_0.01`, `fixed_0.02`, `legacy`, `gentle`. Порядок циклічно збалансовано; RNG кожного методу відновлюється через `make_rngs(97999,task_index,start_index)`. На пробу припадає рівно 5000 нових пошукових оцінювань, разом 200000.

Повний gzip-журнал зберігається до незалежного `verify_log`; невдалий replay не знищує журнал. Кожен worker залишає компактний звіт, помилки, часові вимірювання й SHA-256 маніфест. Зведення перевіряє всі 40 умов, успіх усіх чотирьох jobs і відповідність повних журналів компактним receipts. Підготовка, перевірки початків, оцінювання до мутації й незалежне відновлення мають окремі лічильники; їх не приховують у 5000 запитів. Внутрішні компоненти часу не додаються повторно до зовнішнього wall time.

Зведення дає лише описовий технічний результат і прогноз для **900** калібрувальних та максимум **3600** основних фізичних запусків (2700, якщо дві сталі мітки збігаються). Прогноз часу/журналів має 50% резерву; витрати нових джерел, точних еталонів, майбутніх CI-фаз, бутстрепу й повторень ще не виміряно. Він не є повним кошторисом або дозволом цих серій. На цьому етапі тести, підготовку, ГА та CI не запускали.
