# Доступність покращень і роль операторів під час застою

Протокол GA-KNAPSACK-STAGNATION-MECHANISMS-SECONDARY-V1.

## Питання та межі

Чому алгоритм не знаходить покращення, яке існує поруч із його рекордом? Аналізуємо збережені 900 запусків звичайного генетичного алгоритму для задачі рюкзака. Новий пошук не проводимо. Результати попередньої серії вже переглянуто, тому цей аналіз є вторинним і дослідницьким.

Серед 210 запусків із завершальним застоєм у 202 випадках є кращий допустимий одно- або двобітний сусід. Ці відомі числа слугують перевіркою повноти, а не новим результатом цього етапу.

## Доступність покращень

Для кожного збереженого рекорду незалежно відновлюємо кількість кращих одно- та двобітних сусідів, запас місткості й величини можливого приросту. Перевіряємо всі 5050 записів сертифіката. Додавання, вилучення та обмін предметів розрізняємо.

Для мутації тієї самої маски з імовірністю p шанс отримати одного з цих сусідів без інших змін становить:

P(p) = b1 p (1-p)^(n-1) + b2 p² (1-p)^(n-2).

Розрахунок виконуємо для 0; 0,5; 1; 2; 3; 8%. Він не враховує вибір батьків, схрещування й переходи з трьома або більше змінами. Це пояснення доступності конкретних покращень, а не прогноз успішності всього алгоритму.

## Роль операторів

За журналами відновлюємо батьків, маску після схрещування та кінцеву маску після мутації. Проміжну маску оцінюємо лише після завершення пошуку. Для неї та кінцевого кандидата використовуємо один рекорд, відомий перед відповідним запитом.

Розрізняємо чотири випадки: мутація створила покращення; зберегла покращення проміжної маски; втратила його; жодна з двох масок не покращує рекорд. Допустимість аналізуємо окремо. Остаточний оцінений кандидат, кращий за рекорд, за правилами обліку вже є новим рекордом; його не можна назвати втраченим через відбір.

Окремо аналізуємо всі 5000 нових запитів і останні 1000. Наявність рекорду в завершеній популяції відрізняємо від його перебування серед ще не прийнятих нащадків покоління.

## Вибіркова діагностика

Якщо серед N=5050 сусідів є b кращих, то рівноймовірна вибірка s різних сусідів виявляє хоча б один із них з імовірністю:

D(s,b) = 1 - C(N-b,s) / C(N,s).

Для s=50, 100, 250 обчислюємо точну ймовірність без випадкового моделювання. Вибірка охоплює також недопустимі маски. Зберігаємо всі 210 випадків застою, зокрема вісім без кращого сусіда. Результат для 202 випадків із покращенням позначаємо як умовний.

Знайдений кращий сусід спростовує локальність. Невиявлення такого сусіда вибіркою локальності не доводить.

## Узагальнення

Усереднюємо повторення, потім задачі одного сімейства, потім десять сімейств із рівними вагами. Умовні показники обчислюємо як відношення зважених чисельника й знаменника. Три описові кореляції Спірмена пов'язують сімейні середні кількості кращих одно- й двобітних сусідів та модельної ймовірності при 1% із тривалістю застою. Використовуємо всі 900 запусків; однакові ранги усереднюємо, сталий ряд позначаємо як невизначений. Значень p і причинних висновків немає.

Три рисунки відповідають питанням про доступність покращень, дію операторів і достатність вибіркової діагностики. Назви розміщуємо в підписах, не всередині зображень. Основний приклад незмінний: UC-s000, seed 93001.

## Виконання та готовність

Протокол реєструється окремим комітом до реалізації. Перед запуском потрібен окремий ресурсний дозвіл: запитано до 90 runner-хвилин та 1 GiB компактних виходів. Усі тести, обчислення та рисунки виконуються лише через GitHub Actions. Повні вихідні архіви повторно не завантажуються до сховища доказів як нові дані.

Поточний етап не дозволяє адаптивного порівняння. Для нього надалі потрібен окремий протокол із правилами сигналу, зміни параметра та обліком витрат діагностики.
