# Доповнення: параметри → швидкість → однаковий результат

17.10.2026, до підготовки банків, пілота й основного пошуку нової сітки. Доповнює `GA-KNAPSACK-BASIC-PARAMETERS-V1`, не змінює його бюджет, сітку, відбір переможця чи первинні порівняння. Попередні два запуски були тільки перевірками коду, не результатами GA цієї сітки. Нові показники описові.

## Чіткі питання до рисунків

1. **Скільки оцінювань потрібно до однакової якості?** Для кожного запуску зберігати моменти строгого зростання допустимого рекорду. Визначити T_q як перший загальний логічний запит, де Vbest≥q·V*, для q=0,95;0,99;1. Перевірка цілими числами: 100·Vbest≥95·V*, 100·Vbest≥99·V*, Vbest≥V*. Відсутність досягнення — `NOT_REACHED`, не досягнення на запиті5000.
2. **Який параметр пришвидшує досягнення?** Основний рисунок — три панелі для99% OPT. Змінюємо один фактор по п'яти рівнях, два інші фіксуємо на базових значеннях. ВісьX — загальні логічні оцінювання1…5000, вісьY — сімейно-зважена частка запусків, які вже досягли цілі. Невиходи залишаються в знаменнику. Графіки95% і100% — додаткові перевірки чутливості, не вибір найвигіднішого порогу.
3. **За яких налаштувань результат точно збігається?** Для кожної пари «та сама задача—той самий seed» порівняти кінцеву цілу цінність зі сталою базовою конфігурацією(1%;90%;30). Показати частку точних збігів за конфігураціями; окремо — частку вищих і нижчих значень. Не порівнювати абсолютні цінності різних задач. Однакове середнє не означає однакові парні результати.
4. **Чи досягаємо того самого набору цінності раніше?** Для наперед визначеного прикладу UC-s000, seed81001, згрупувати125 конфігурацій за однаковою кінцевою цілою цінністю та показати перший запит до неї. Показати всі групи, не лише успішну. Однакова цінність не гарантує однакової маски; це не тест статистичної еквівалентності. Додатково для кожного запуску визначати перший запит до кінцевої цінності базового ГА з його повного журналу рекордів.

Сімейне усереднення: повторення → задача → UC/WC/SC одного індексу → десять рівноважних сімейств. Порогові часи включають оцінки початкової популяції; її перевага не приховується. Розміри популяцій порівнюються за оцінюваннями, не поколіннями й не незіставним часом різних CI-машин.

## Модель і докази

Додати окремий короткий опис математичної моделі рюкзака, псевдокод одного класичного ГА й посилання на фактичне незмінене ядро. Параметри p_m,p_c,μ мають бути в таблицях, підписах і легендах; у сталій серії вони не змінюються під час одного запуску.

Спостерігач працює після завершення пошуку та незалежного відновлення журналу. Він не повертає ціль, оптимум чи часи алгоритму. Компактна історія рекордів відтворюється з усіх оцінених допустимих кандидатів, включно з початком, дублікатами й завершальним неповним поколінням. Перевіряльник відхиляє неправильний порядок запитів, спадання рекорду, хибні кінцеві значення, часи поза бюджетом і змішування ідентичностей.

Усі тести, обчислення й рисунки — тільки CI, в уже погоджених межах60/900 runner-хвилин та40GiB. Нових GA-запусків поза зареєстрованою серією це доповнення не дозволяє. Допуск адаптивного контролера й остаточний holdout залишаються закритими.

*Швидке досягнення гіршого власного результату не означає кращого алгоритму: головне порівняння використовує спільні95/99/100% OPT. Точні збіги цінностей не доводять еквівалентності методів. Жодних позитивних закономірностей до результатів не обіцяємо.*
