# Початкові параметри ГА для 100 предметів

Протокол зареєстровано до реалізації. Дослідження уточнює сталу пару «популяція та схрещування», після чого перевіряє вибір на нових задачах. Мутація становить 1%, відбір виконується з двох особин, зберігається одна еліта. Гранична кількість оцінювань дорівнює 100 000 разом із початковою популяцією.

Сітка містить популяції 10, 15, 20 і 25 та схрещування 70%, 80%, 90% і 100%. Підбір включає 1440 результатів на 30 переглянутих задачах і трьох спільних повтореннях. Для двох комбінацій за 90% допускається повторне використання 180 перевірених записів після підтвердження походження та сумісності. Незалежна перевірка включає обрану пару та сталі контроли 10/90 і 20/90 на сімействах s060–s069.

Інтерфейс `run_ga(...)` і цикл еволюції імпортуються з зафіксованого історичного ядра. Обв’язка задає сталі параметри через контракт `population-crossover-v1`. Пошуковому ядру не передаються OPT та точні сертифікати. Показники обчислюються після пошуку.

Код цього каталогу не відтворює опублікований авторський алгоритм. Допуск стосується власного контрольованого експерименту: заданий контракт підтримує потрібні параметри; джерела KPLIB зафіксовані commit і Git blob; походження, ліцензія, дублікати та два точні еталони перевіряються до нового пошуку. Пріоритет нового алгоритму не заявляється.

Усі тести, точне розв’язування, пошук, числовий аналіз і рисунки виконуються виключно в GitHub Actions. Локально допускаються підготовка коду, огляд, облік файлів і контрольних сум. Історичні файли не редагуються.

Технічний дозвіл, підбір і незалежна серія мають окремі ресурсні погодження. Поточний стан дозволу записано в `resource_authorization.json`; початковий стан не дозволяє обчислень. Залишок попереднього дослідження не використовується.

Для підбору заздалегідь збережено окремий набір початкових банків і компактних журналів попереднього дослідження. Підготовка перевіряє походження, цілісність і рівно 180 потрібних записів; решта повторень не використовується під час вибору. Новий пошук розділено на 210 блоків по шість випадків. Для кожного випадку зберігається журнал і окремий запис незалежної перевірки. Блок із помилкою зберігається разом із завершеними випадками; повторний запуск усього блоку заборонено. Перед продовженням потрібно сформувати реєстр лише відсутніх ідентичностей та перевірити залишок погодженого ресурсу.
