# Мутація та популяція: доповнення першої демонстрації

Статус: реалізацію підготовлено; окремий ліміт до 20 runner-хвилин погоджено відповіддю «Погоджую до 20 runner-хвилин». Перевірки й аналіз запускаються тільки на точному SHA; наявність дозволу сама по собі не означає успішної перевірки.

Це вторинний описовий аналіз завершеної серії, а не новий пошук ГА. Порівнюються профілі 0, 1, 4, 5: сталі параметри, адаптивна мутація, адаптивна популяція, обидва правила. Усі інші механізми сталі. По 900 історичних запусків на профіль, 3600 загалом.

## Інтерфейс і послідовність

Окремий workflow `knapsack-mutation-population-review.yml` приймає єдиний маркер `[mutation-population:review]` у коміті поточної гілки. Точний SHA, незмінні залежності й окремий ресурсний дозвіл перевіряються перед роботою. Без `explicit_user_approval: true` gate завершується блокуванням. Не запускати workflow з маркером до погодження.

Команди `driver preflight --output ...` та `driver review --permit ... --output ...` призначені тільки для зареєстрованого CI. Друга фаза спочатку виконує програмні приклади, потім перевіряє всі 28 800 джерельних ідентичностей, відбирає 3600 попарних записів, відновлює чотири історичні журнали незалежним verifier і будує шість окремих рисунків. Вона не імпортує й не викликає пошукове ядро.

Результат: зведення, чотири траєкторії, контрольні точки фактичної й цільової популяції, 3600 компактних кінцевих результатів, рисунки PNG/SVG, опис меж аналізу, журнал перевірки й маніфест SHA256. Нових довірчих інтервалів чи первинних перевірок немає. Шість історичних первинних порівнянь залишаються незмінними.

Нові локальні редакції основного документа, презентації на 13 слайдів та короткого пояснення готуються лише після успішної перевірки цього результату. Попередні документи не перезаписуються. Локальні матеріали не входять до Git.
