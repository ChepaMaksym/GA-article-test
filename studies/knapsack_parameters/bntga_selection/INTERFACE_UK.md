# Однозначний інтерфейс незалежного оператора

Уточнення до реалізації, 17.10.2026. Протокол і джерельний допуск залишаються незмінними.

- Точка: рівно `id` (непорожній рядок), `objectives` (непорожній список скінченних чисел, усі мінімізуються), `selected` (ціле невід'ємне, не bool). Усі точки мають однакову розмірність. Повторний id із різними координатами відхиляється; рівні вектори різних id допускаються у вхідній партії й усуваються за протоколом.
- `update_archive(new_points, existing=())` повертає новий список: старі недоміновані точки у своєму порядку, потім допустимі нові у порядку партії. Новий selected завжди 0. Вхід не змінюється. Existing уже має бути неповторним недомінованим архівом.
- `freeze_selection(archive, dimension, balanced=True)` повертає план із полями `schema`, `archive`, `dimension`, `balanced`, `gaps`, `priorities`. schema=`bntga-frozen-plan-v1`. Архів у плані відсортований за координатою й регістрозалежним id. Для більш ніж однієї точки dimension — цілий індекс координати. Різниця координат має залишатися скінченною й не перевищувати максимального float32; інакше відмова, не обрізання.
- Для singleton dimension має бути `None`, gaps=[None], priorities=[None]: джерельний ранній вихід не виконує вибору координати або розрахунку Gap. Це явний стан, не пропущена наукова оцінка.
- `select_pair(plan, current_counts, tournament_draws, neighbor_side=None)` приймає лічильники як dict id→selected, із точним набором id і значеннями не нижче планового знімка. Індекси турніру адресують ВІДСОРТОВАНИЙ план. Для >1 точки потрібен непорожній список індексів. На краю neighbor_side=None; усередині 0 означає наступного, 1 — попереднього сусіда, як у перевіреному коді. Для singleton потрібні порожній список витягувань та neighbor_side=None.
- Подія містить рівно `schema`, `tournament_draws`, `neighbor_side`, `first_index`, `second_index`, `first_id`, `second_id`, `first_priority`, `counts_before`, `counts_after`, `singleton`. schema=`bntga-selection-event-v1`. У singleton first_priority=None. Лічильники повертаються копіями; вхід не мутується. Balanced та unbalanced обидва журналюють використання точок, але лише balanced використовує історію у знаменнику. Це чиста абляція, не авторський non-BNTGA перемикач із іншими краями другого батька.
- `build_journal(initial_points, blocks, balanced)` — evaluator-free обв'язка. Кожний блок задає `dimension`, `requests` (список пар tournament_draws/neighbor_side), `new_points` (відомі оцінки, надані ззовні після вибору). Після всіх виборів лічильники з'єднуються з id, потім оновлюється архів новою партією. Ніякого нового fitness тут не обчислюють.
- Журнал має рівно `schema`, `balanced`, `initial_points`, `initial_archive`, `blocks`, `final_archive`, `accounting`; schema=`bntga-operator-journal-v1`. Кожний блок: `archive_before`, `plan`, `requests`, `events`, `archive_after_selection`, `new_points`, `archive_after_update`. Accounting: `selection_pairs`, `objective_vectors_supplied`, `new_fitness_evaluations` (завжди 0).
- Незалежний `verify_journal(journal)` заново відновлює архів, скінченні Gap, пріоритети, вибір, лічильники та облік без імпорту виробничого оператора. Результат — статус VERIFIED, число пар та нових fitness=0. Це перевірка оператора, не пошуку, не якості й не ліцензійного відтворення авторського коду.

Об'єктивні координати надходять іззовні вже у визначеному просторі. Авторський код використовує нормовані оцінки; наш загальний оператор працює в поданому просторі. Мапування ваги/цінності й нормування конкретного рюкзака цим інтерфейсом не визначені й не допущені.
