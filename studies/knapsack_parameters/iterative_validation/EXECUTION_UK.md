# Перший запуск: діагностика готових результатів

Перша спроба 44057797206 завершилася: 18 тестів пройдено, аналіз зупинено через помилкову вимогу до історичного шляху артефакту. Виправлення описано в [RECOVERY_UK.md](RECOVERY_UK.md). Додаткова ручна спроба очікує підтвердження; сукупна межа 20 runner-хвилин і 500 MiB зберігається.

Статус: погоджено до 20 runner-хвилин і 500 MiB на одне виконання першої діагностики. Публікацію пакета також погоджено. Повторне виконання ще не проведено. Команди нижче належать лише середовищу GitHub Actions. Локально виконувати їх для цього етапу не передбачено.

## Склад і обсяг

Вхід: незмінна копія `data/validated_records.json.gz`, історична таблиця `data/all-configurations.csv` та зафіксований вибір `data/selection.json`. Повний набір містить 2790 записів, а докладне порівняння чотирьох конфігурацій містить 360 записів. Нові оцінювання пошуку не виконуються.

Перед початком фіксуються `source_manifest.json`, контрольна сума протоколу та дозвіл `resource_authorization.json`. Стан дозволу `PREPARED_NOT_AUTHORIZED` відхиляє виконання до програмних тестів і числової обробки. Після явного погодження змінюються лише поля дозволу; за зміни програмного коду або вхідних матеріалів відбиток формується заново.

Workflow: `.github/workflows/iterative-validation.yml`.

Гілка виконання: `research/iterative-validation-20261117`.

Подія: лише `workflow_dispatch`, обов’язковий параметр `authorization_id`. Для першого етапу використовується одне завдання з межею 15 хвилин; запропонований сукупний ліміт становить 20 runner-хвилин із резервом. Одночасні багатозадачні фази надалі обмежуються чотирма завданнями; автоматичного переходу до нового експерименту немає.

Цей ліміт є запобіжником до першого вимірювання, а не виміряним прогнозом. Повторний запуск не входить до одноразового доручення. Програма відхиляє повторну спробу того самого run ID; нові ручні run ID потрібно контролювати за журналом фактичних запусків.

## Що виконує сценарій

1. Перевіряє новий дозвіл, ручну подію, репозиторій, гілку та контрольні суми підготовленого комплекту.
2. Установлює Python 3.12.14 і залежності з історичного файла з контрольними сумами.
3. Виконує синтетичні тести порогів, парності, усереднення та захисту виконання.
4. Перевіряє повноту 2790 компактних записів і відтворює показники з історії рекордів.
5. Формує шість описових парних порівнянь, сімейні оцінки та діагностику вилучення одного сімейства.
6. Створює звіт, CSV, PNG, SVG і PDF. Перевіряє граничний обсяг перед збереженням артефактів.

Пошукове ядро, генерація початків і точне розв’язування не імпортуються. Аналіз компактних записів не є новим відновленням повних журналів. Збережені суми банків і операторних артефактів перевіряються на узгодженість; їхній первинний вміст у цьому пакеті відсутній.

## Очікувані матеріали

Артефакт `iterative-validation-first-analysis-<run_id>`:

- `meta/admission.json`, `tests.txt`, `execution-status.json`;
- `analysis/summary.json`, `provenance.json`;
- `analysis/run-metrics.csv`, `paired-differences.csv`, `paired-summary.csv`;
- `analysis/family-metrics.csv`, `family-differences.csv`, `leave-one-family-out.csv`;
- `analysis/ranking-audit.csv` для всіх 31 конфігурації;
- короткий звіт `report.md`, `short-report.pdf`, альбом `figure-album.pdf`;
- вісім окремих рисунків у PNG і SVG та `figure-metadata.json` із підписами.

Усі частки досягнень мають знаменник 90. Графіки 93%, 95% і 99% оптимуму мають окремі осі та шкалу 0–100%. Число оцінювань включає початкові особини. Сирі журнали й активність операторів заново не перевіряються; відповідна прогалина залишається у звіті.

Фактичний обсяг артефактів друкується в журналі кроку перевірки обсягу workflow.

Після завершення потрібно зберегти run ID, ідентифікатор версії коду, фактичні хвилини й розмір артефакту, завантажити матеріали до `ДИПЛОМ/Мікродослідження/01_Внесок_і_швидкість/` та передати готовий звіт незалежному агенту для висновку. Популяція 13 автоматично не запускається.

## Обмеження керування GitHub

Підключений інструмент GitHub підтримує публікацію файлів і читання результатів, але не надає команди ручного запуску workflow. Після реєстрації сценарію запуск через інтерфейс GitHub виконується кнопкою **Run workflow**, з вибором зазначеної дослідницької гілки й погодженого `authorization_id`. Автоматичний тригер публікації гілки не додається.
