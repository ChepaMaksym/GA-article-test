# Технічний пілот: реалізація та докази

Дозвіл: `GA-DIVERSITY-CROSSOVER-TECHNICAL-PILOT-V1`, окремий коміт протоколу `760c14b`. Це не повна наукова серія і не реплікація чисел статей.

## Межі модулів

| Модуль | Призначення |
| --- | --- |
| `contract.py` | Гілка, SHA, незмінність протоколу й історичних входів, середовище, сукупні runner-хвилини |
| `engine.py` | Спільне ядро трьох методів; без доступу до оптимального набору й сертифікатів |
| `verifier.py` | Незалежне відновлення операторів, генераторів, популяції, оцінок і показників |
| `banks.py` | 16 наперед визначених початків; початковий кеш лише під час підготовки |
| `runner.py` | Вісім фізичних запусків однієї задачі, стиснені журнали та перевірка |
| `reporting.py` | Повнота 64 запусків, описові підсумки й наперед визначені ілюстрації |
| `ci_support.py` | Квитанція тестів, безпечне завантаження й перевірка ZIP-архівів CI |

## Послідовність

Окремий коміт протоколу → коміт коду `[diversity:tests]` → зафіксована квитанція зелених тестів `[diversity:prepare]` → коміт банків `[diversity:pilot]` → підсумковий коміт без маркера.

Невідомий, змішаний або незареєстрований маркер не дозволяє пошук. Реалізація й workflow мають збігатися за файловими хешами на всіх трьох фазах. Кожна фаза перевіряє використання всіх попередніх спроб через GitHub API; невідомі витрати або недостатній залишок блокують її.

Локальне виконання тестів, підготовки, пошуку, аналізу й наукових графіків заборонене. Не встановлюйте `GITHUB_ACTIONS` штучно для обходу цього обмеження.

## Що зберігати

У Git — код, протокол, квитанція перевірок, початки та компактні підсумки. У CI та одній локальній доказовій копії — повні журнали й ZIP. Word і локальний журнал прогресу не пушаться.

Успіх пілота означає правильність обліку, 64/64 завершених запусків і відсутність розбіжностей незалежної перевірки. Один seed не встановлює переваги, статистичної потужності чи новизни. Погані результати не замінюються.
