# Зворотний зв’язок для адаптації параметрів ГА: звіт про джерельний допуск

Етап 2. Дата: 12 жовтня 2026 року. Результат: SOURCE_NO_GO_FOR_GLOBAL_CONTROLLER. Це завершений аудит відповідності джерела погодженому дизайну, не виконаний експеримент порівняння алгоритмів.

## 1. Питання та погоджена умова завершення

Дослідження мало зіставити адаптивні ймовірності мутації та схрещування з незалежним готовим розкладом, переставленим розкладом і сталими налаштуваннями. Генетичний алгоритм (ГА) мав використовувати 30 особин, одну еліту та 29 нових нащадків у поколінні. Параметри повинні бути однаковими для всього покоління й змінюватися після його завершення.

Погоджений план прямо вимагав спочатку допустити точне джерельне правило. Якщо відповідного глобального правила немає або воно недовизначене, етап завершується звітом про недопуск; код і пілот не запускаються. Саме цю гілку виконано.

*Наукове питання про користь зворотного зв’язку залишається невирішеним. Результат аудиту не є негативним результатом виміряної ефективності адаптивного ГА.*

## 2. Перевірене джерело та походження доказів

Перевірено статтю Rajagopal та співавторів «An Automated Path-Focused Test Case Generation with Dynamic Parameterization Using Adaptive Genetic Algorithm (AGA) for Structural Program Testing», Information, 2023, 14(3), 166 [1]. Офіційний PDF містить 18 сторінок; його отримано з сервера видавця, а не з неофіційної копії. Сторінка 1 підтверджує ліцензію CC BY 4.0 та афіліацію четвертого автора в University of West Attica, Греція. Отже, рік і географічна вимога виконані.

Вихідні PDF і рисунок 3 збережено без редагування, з розмірами та SHA256. Повторне завантаження не потрібне для читання збереженої версії. Детальні ідентифікатори містяться в реєстрі джерел, не в основному викладі.

Текст PDF прочитано з його текстових потоків; окремі математичні шрифти мають спеціальні коди. Рисунок 3 додатково перевірено за оригінальним зображенням видавця. Автоматичне вилучення тексту не підміняє візуальну перевірку неоднозначного математичного символу. Висновок спирається насамперед на явну залежність від f(i), P(i) та P(0).

*Отримання повного тексту доводить доступність джерела, але не повноту алгоритмічного контракту. Публічний авторський код у перевірених матеріалах і цільовому пошуку не встановлено; це не твердження, що такого коду ніде не існує.*

## 4. Математична причина недопуску

На сторінці 9 для мутації використано дві гілки. Позначимо N(DPD) нормованою різноманітністю. Для особини з оцінкою не нижче середньої формула (7) має вигляд:

Формула 1 — Верхня гілка індивідуального правила джерела

$$P_{M,i}=P(i)(1-N(DPD))$$

Для особини з оцінкою нижче середньої використано:

Формула 2 — Нижня гілка індивідуального правила джерела

$$P_{M,i}=P(0)$$

Це правило для конкретної особини i. Наш дизайн натомість потребує одного p_m для всіх 29 нащадків покоління. Без явного переходу від індивідуальних значень до глобального параметра ці два контракти не тотожні.

Нормування у тексті подано як:

Формула 3 — Нормування різноманітності у джерелі

$$N(DPD)=DPD/(DPD+\Delta)$$

Зазначено додатність константи Δ. Важливе уточнення: на сторінці 7 число 0,01 уже наведено для константи функції придатності. Тому некоректно стверджувати, що числового значення Δ взагалі немає. Водночас це не відновлює відсутнього визначення DPD та індивідуальних базових ймовірностей.

Для старту однаковими копіями потрібна однозначна метрика на плоскій популяції. Самої формули нормування недостатньо, якщо величину, яку нормують, неможливо відновити за джерелом. Поведінку таких станів не дописано за здогадкою.

Побутове пояснення: стаття задає правила для різних людей окремо, а наше порівняння потребує одного правила для всієї групи. Якщо самостійно усереднити індивідуальні рішення, це вже наше нове правило. Приклад пояснює різницю контрактів, не є результатом експерименту.

*Формули тут наведено для аналізу джерела. Їх не реалізовано як контролер рюкзака і не перевірено новою експериментальною серією.*

## 6. Вердикт і наступне рішення

Вимоги до джерельного допуску для цього дизайну не виконані. Етап коректно завершено на передбаченому запобіжнику; експериментального висновку про користь зворотного зв’язку немає.

Продовження потребує одного окремого рішення користувача: інше однозначно описане сучасне джерело для глобальних параметрів або власна проєктна модифікація з наперед визначеними правилами. Ці варіанти не виконуються автоматично в межах поточного плану.

До диплома можна включити постановку нового питання, матрицю простежуваності й обґрунтування відмови від прихованого усереднення. Не можна включати висновок про перевагу адаптивного алгоритму, новизну реалізованого контролера або результати невиконаного пілота.

*Це результат перевірки відтворюваності конкретного перенесення, а не доказ, що адаптивне керування параметрами не працює. Не встановлено нового алгоритму, практичного впровадження або універсального ефекту.*
