# EU26-02 eligibility re-audit — 2026-08-07

Decision: **retain `conditional_noneligible`; authorize only an
`ARCHIVE_AND_FORMULA_VALIDATION_ONLY` scaffold.**

The official Deleter archive at code commit
`04da9dd489f6e8e76fa3504d105c137bdf9ea323` has SHA-256
`1b7e8cf1ef637005bd994104f6e1ee520256ed387994b126bbe875a137632e41`.
Using the repository's own unfiltered final-row aggregation maps the archive
exactly to every AHEAD+Deleter cell in the paper's 31-row GCP Table 2. This
resolves which artifact produced the table.

It does not resolve the protocol gate. The paper states one hour per GCP run;
the job generator sets 10,800 seconds, all archived headers record 10,800
seconds, and the table generator's 3600-second filter is commented. Target
retries also run as separate jobs. G8 and G9 therefore remain unresolved and
the candidate cannot receive a score or `hard_pass` label.

The source audit also corrects the former G5 description: code Deleter has no exploration floor. It samples
uniformly from six surviving operator pairs, tracks lifetime mean child
penalty, and deletes the largest mean every fifth source turn after turn 30
until one pair remains.

A deeper pass changed G5 and G10 from pass to unresolved. The paper specifies
a last-50 reward queue and insertion-before-update, while the code uses a
lifetime mean and update-before-insertion. The archive contains `restart`
sentinels absent from that revision, and its OpenMP work shares mutable RNG and
solution-counter state. The scaffold therefore validates source semantics and
archive provenance as separate tracks; it cannot join them into a published
execution contract.

Allowed work is limited to pinned archive replay, independent Python and
MATLAB/Octave transition validation, native build/micro-run evidence, and
deterministic hardware checks. `PASS_FULL` is forbidden while the budget
conflicts remain.
